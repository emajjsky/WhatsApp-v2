# 当前进度

更新日期：2026-08-22

## 一句话说明

当前项目已经拆成两条交付路线：

- `main`：云端 Web 部署版，继续作为服务器 Web 使用路径。
- `Electron-desktop`：桌面安装包 + 云端鉴权后台路径，当前重点开发和测试这一条。

两条路线不要混着改。云端 Web 版问题修 `main`，桌面安装包问题修 `Electron-desktop`。

## 本轮新增：本地代理池与账号级出口 IP

已开始实现 Electron 本地代理方案：

- 新增本地代理池页面，可保存多个 HTTP/HTTPS/SOCKS5 代理。
- 代理用户名和密码只进入当前电脑的本地数据库，不上传云端。
- 密码使用本地生成的 AES-256-GCM 密钥加密保存，接口和列表不会返回密码。
- 账号页面增加代理选择框；未选择代理时使用本机 IP。
- 每个 WhatsApp 账号按自己的代理创建独立的 whatsmeow 客户端。
- 代理检测支持通过 SOCKS5/HTTP 请求查询出口 IP。
- 代理失效或过期时不会静默回退到本机 IP。
- 账号切换代理后需要退出并重新连接，避免旧长连接继续使用旧出口。

## 0.1.39 自动链式代理状态

- 本地代理池增加 `自动判断`、`直连代理`、`强制链式`三种连接方式。
- Electron 通过本机运行时接口动态读取 Clash/Windows 系统代理，不需要用户手工填写 Clash 端口。
- 链式连接统一覆盖 WhatsApp Web 版本检查、二维码、WebSocket、媒体上传下载。
- 已连接账号每 20 秒检查系统代理入口变化，Clash 切换节点后自动重连受影响账号。
- 自动模式在境外无系统代理时直接连接账号代理；强制链式模式检测不到系统代理时明确失败，不静默直连。
- 仍需一账号绑定一个独立代理；单个 Clash 节点不能自动产生多个出口 IP。
- 账号页的出口配置已与“创建账号卡片”分离，当前账号单独显示绑定代理、路由方式和出口 IP，不会互相覆盖。
- 代理检测已区分 IP 检测和 WhatsApp Web 可达性；`auto` 模式在系统代理不可用时直连独立代理，`system` 模式则明确失败。
- Electron 已增加本机链路状态机制：实时显示系统代理规则、代理端口可达性、外层出口 IP、检测时间和自动/直连/手动结论；支持“立即检测”和 30 秒自动刷新。
- 已明确区分两层验证：顶部状态卡验证 Clash 外层，代理列表的“检测”验证“外层 Clash → 独立代理”的真实链路，不再用单一地址推断链式已经生效。

本轮验证：

- `npm run build` 通过。
- Docker Go 环境下 `internal/proxychain`、`internal/proxies`、`internal/sessions`、`internal/platform` 测试通过。
- 双层 SOCKS5 测试已验证“外层代理 → 内层代理 → 目标服务”的真实拨号路径。
- `go test ./...`、`go vet ./...`、`node --check desktop/src/main.cjs` 和 `git diff --check` 已通过。

## 0.1.36 本机代理编辑修复

- 已保存代理支持直接编辑名称、协议、地址、端口、账号、出口 IP、地区和有效期。
- 编辑时密码留空表示保留原密码，接口不会向前端返回密码。
- 代理仍绑定 WhatsApp 账号时可以通过编辑更新，不会误删绑定关系。
- 重复代理名称会提示使用编辑功能或更换名称。

## 0.1.37 代理删除修复

- 删除代理时先在同一数据库事务中解除当前用户的账号绑定，再删除代理配置。
- 删除不会删除 WhatsApp 账号、聊天记录或本地会话数据。
- 删除后账号回到本机网络；如需立即切换出口，需要重新连接账号。

本轮代码验证：

- `npm run build` 已通过。
- Docker Go 环境执行 `go test ./internal/...` 已通过。
- 已增加代理凭据加解密和 `socks://` 转 `socks5://` 单元测试。

当前测试代理实测可以建立 TCP 连接，但 SOCKS5 服务端拒绝了认证，返回 `User was rejected by the SOCKS5 server`。这通常是测试凭据已失效、账号密码复制错误或测试时长已到，不是客户端代码的连接超时。购买正式月套餐前需要让供应商重新开一条测试凭据再验证。

### 2. 智能体配置

- 回复 Agent 支持云端统一配置。
- 翻译 Agent 支持云端统一配置。

- 桌面端用户不需要在本机填写模型 API Key。
- 桌面端通过本地 API 代理到云端 Agent 执行，返回结果后再写入桌面端界面。

### 3. 桌面端能力

- 桌面端负责本机 WhatsApp 登录、二维码、会话、消息、媒体和导出。
- 桌面端支持自动检测系统代理、直连、手动代理三种 WhatsApp 网络模式。
- 代理配置已经放到界面，不需要普通用户手改配置文件。
- 桌面端登录后可以根据云端授权控制可用能力。


安装新版本通常可以直接覆盖安装，不需要先卸载旧版本。

### 5. 桌面端 AI 助手界面

已完成本轮桌面端 AI 助手前端整理：

- 顶部工具栏统一为 `选择智能体客服`、智能体下拉框、上下文开关、历史轮数和生成按钮。
- 右侧辅助面板固定显示回复方案、采纳区、翻译结果区，不再因为未生成内容而塌陷。
- 生成回复建议前，三张方案卡保持显示并标记 `待生成`。
- 生成三套回复策略后，整体状态变为 `待采纳`，每张方案卡显示 `采纳`。
- 点击某一方案后，该方案按钮变为 `已采纳`，采纳区状态也同步为 `已采纳`。
- 切换会话再回来，回复方案、草稿、译文和采纳状态会保留在当前会话缓存里。
- 状态卡区域已压缩为顶部状态条，避免挤占聊天窗口高度。

### 6. 状态卡问题修复

已修复桌面端状态卡保存失败的问题。

原因是桌面本地数据库的 `chat_status_cards.agent_id` 原本强依赖本地 `system_agents`，但现在桌面端使用的是云端 Agent ID，本地不存在对应记录。

处理方式：

- 新安装数据库不再给 `chat_status_cards.agent_id` 加本地外键。
- 老数据库通过新 migration 删除旧外键约束。

相关迁移：

```text
deploy/migrations/0017_chat_status_cards_cloud_agents.sql
```

- 后续如果客户需要集中审计或服务顾问统一查看聊天记录，再单独设计上传任务和服务端存储。

- 自动检测系统代理后先校验本地代理端口是否可连接，失效的 Clash 旧端口不会继续注入 WhatsApp 连接。

- 回复方案 `待生成` / `待采纳` / `已采纳` 状态流转。

## 下一步建议

1. 使用本机 IP 先完成登录、对话、智能体和导出功能测试；不需要等待代理可用。
2. 国外客户在客户端“IP代理”页面填写自己的固定代理，检测到预期出口 IP 后再绑定 WhatsApp 账号。
