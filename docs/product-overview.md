# WhatsApp Agent Windows 桌面客户端 + 云端鉴权后台产品文档

更新日期：2026-08-20

## 1. 产品定位

WhatsApp Agent 是一套面向跨境电商客服、海外私域运营和 WhatsApp 多账号服务团队的桌面端智能客服工作台。它的核心形态不是让用户去部署一套复杂的 Web 系统，而是让客服安装 Windows 客户端后直接使用；云端只承担登录鉴权、权限控制、智能体配置、话术包管理和数据复盘这些统一管理能力。

这套产品解决的是跨境客服日常最费劲的几件事：多个 WhatsApp 账号需要同时管理，客户来自不同国家和地区，客服需要快速看懂多语种消息，还要按照统一话术把客户引导到入群、私域或下一步转化动作。AI 不替代客服直接乱发消息，而是提供回复策略、翻译和客户状态判断，最终由客服采纳、编辑和发送。

## 2. 适用场景

产品适合跨境电商客服团队、海外私域团队、WhatsApp 运营团队和服务顾问团队使用。典型场景是一个客服需要维护 20 到 50 个 WhatsApp 账号，客户消息分散在不同账号和会话里，业务侧又要求客服及时回复、统一话术、减少误解，并且能把关键沟通过程导出或复盘。

对中国籍客服来说，多语言是很现实的问题。客户可能使用英语、西语、阿拉伯语、日语、东南亚语种或其他语言，客服不一定懂这些语言。系统通过消息翻译、中文草稿、目标语种翻译这一套流程，让客服先用中文判断和编辑，再把最终内容翻译成客户语言。

对管理者来说，真正重要的不是“AI 有没有生成过内容”，而是客服最后采纳了什么、改成了什么、写回或发送了什么。因此产品保留采纳数据，用于后续质检、培训、话术优化和智能体提示词优化。

## 3. 产品价值

### 3.1 降低使用门槛

Windows 客户端做成安装包后，普通用户不需要安装 Docker、PostgreSQL、Go、Node、Python，也不需要理解服务器部署。用户安装软件、登录账号、扫码接入 WhatsApp，就可以进入工作台处理消息。

### 3.2 降低服务器和 IP 风险

WhatsApp 登录、会话连接、聊天消息、媒体收发和导出主要运行在用户本地。这样可以避免所有 WhatsApp 账号都从同一台服务器出口 IP 出去，降低集中登录和集中网络出口带来的风控压力。云端只负责统一鉴权和智能能力，不直接承载全部 WhatsApp 账号连接。

需要注意：本地运行只解决“所有客户共用服务器 IP”的问题；同一台电脑上的多个 WhatsApp 账号目前仍会共用本机出口或同一个全局代理。生产阶段计划增加账号级固定代理绑定，让每个账号使用独立且粘性的出口 IP，具体见 `docs/account-level-proxy-design.md`。

### 3.3 统一智能体和话术

管理员在云端后台配置回复智能体、翻译智能体、状态卡智能体和 Skill 话术包。普通客服不需要自己填写模型 API Key，也不需要自己配置提示词。后台配置好后，客户端登录用户即可使用统一的智能体能力。

### 3.4 提升客服效率

客服可以在对话页生成三套不同策略的回复建议，采纳其中一套后继续编辑中文草稿，再翻译为客户语种并写回或发送。这个流程比完全手写更快，也比全自动回复更稳。

### 3.5 支持客户状态判断

系统可以基于聊天历史生成用户状态卡，分析客户当前阶段、客户类型、风险等级、摘要和下一步建议。客服不需要每次翻几百条历史消息，也能快速判断该推进、解释、安抚、催促还是复访。

### 3.6 支持管理复盘

后台记录客服点击写回或发送时的采纳数据，包括 WhatsApp 账号、客户 ID、客户昵称、客户最新消息、采纳方案序号、采纳方案原文、编辑后的中文原文、翻译结果和动作时间。管理者可以查看、筛选和导出，用于质检与培训。

## 4. 产品架构

当前产品由 Windows 桌面客户端和云端鉴权后台组成。

| 模块 | 主要职责 | 数据位置 |
| --- | --- | --- |
| Windows 桌面客户端 | WhatsApp 扫码登录、账号管理、对话查看、消息收发、媒体处理、聊天导出、AI 助手界面 | 用户本地 |
| 本地 API 服务 | 客户端内部服务，负责连接 WhatsApp、管理本地数据、代理调用云端智能体 | 用户本地 |
| 本地数据库 | 保存账号、会话、消息、媒体索引、导出任务、状态卡缓存等 | 用户本地 |
| 云端鉴权后台 | 登录注册、邀请码、用户权限、设备授权、智能体配置、Skill 管理、采纳数据查看 | 云端服务器 |
| 云端 Agent Runner | 执行回复、翻译、状态卡等智能体调用 | 云端服务器 |

这套架构的核心思路是：WhatsApp 账号资产和聊天数据尽量留在用户本地，AI 能力和管理能力放在云端统一维护。这样既方便发安装包给用户使用，又方便管理员统一控制谁能登录、谁能使用哪些能力、系统用哪套智能体和话术。

## 5. Windows 桌面客户端功能

### 5.1 客户端登录

用户打开 Windows 客户端后，需要先登录云端账号。普通用户通过管理员发放的邀请码注册，管理员可以在后台控制用户是否允许使用桌面端。

客户端登录后的可见功能主要包括账号接入、对话查看、话术、导出中心。管理员账号登录客户端时，也可以进入后台页面查看管理能力，后台数据与云端配置保持一致。

### 5.2 WhatsApp 账号接入

客户端支持创建多个 WhatsApp 账号卡片，并通过二维码或配对码完成登录。每个账号可以查看状态、退出登录或删除。

账号连接运行在本地客户端内，因此用户所在电脑的网络环境会影响 WhatsApp 连接。客户端支持三种网络模式：自动检测系统代理、直连、手动代理。国内用户可以走系统代理，国外用户可以直连，特殊网络环境下也可以手动填写代理。

### 5.3 对话查看

对话页是客服工作台的核心。客服可以按账号、聊天类型和关键词筛选会话，查看单聊、群聊等不同类型消息。

当前支持展示和处理文字、图片、视频、文件、音频等媒体消息。客服可以发送文字和媒体消息，并通过实时更新机制接收新消息。

### 5.4 消息翻译

对话中检测到非中文消息时，会出现翻译按钮。客服点击后，系统将客户原文翻译为中文，并标注原文语种。翻译结果会缓存，切换对话再回来不会重复调用。

用户自己发送过的非中文消息也可以翻译为中文，方便中国客服回看历史话术，避免因为外语内容看不懂而影响判断。

### 5.5 AI 助手

右侧 AI 助手用于生成、采纳、编辑和翻译回复建议。客服可以选择回复智能体，设置是否携带上下文，并配置历史消息条数。默认上下文为 20 条。

点击生成后，系统输出三套不同策略的回复方案。未生成时方案区保持固定布局，显示待生成；生成后显示待采纳；客服点击采纳后显示已采纳。采纳后的中文内容进入草稿区，客服可以继续编辑。

编辑后的中文草稿可以翻译为客户语种。翻译完成后，客服可以写回输入框进行最后检查，也可以直接发送。只有点击写回或发送时，系统才记录采纳数据。

### 5.6 多会话状态保持

客户端已经按会话隔离 AI 助手状态。客服在 A 对话生成回复，再切换到 B 对话生成回复，两边的生成状态、方案、草稿、译文和采纳状态应当独立保存。切换对话或刷新页面后，最新生成结果不会无故消失。

这点很关键，因为真实客服不会只处理一个客户。多会话并行时，回复建议和翻译结果不能混在一起，也不能因为一个会话完成翻译就影响另一个会话发送。

### 5.7 用户状态卡

对话窗口上方显示用户状态卡。状态卡会基于聊天历史分析客户当前阶段、客户类型、当前风险、摘要和建议。

当前阶段包括新线索、已破冰、问费用、问进群、已进群、问推荐、问操作、异议中、check-in、沉默待复访。客户类型包括新手、有经验、曾亏损、价格敏感、信任不足、操作小白、高意向。风险分为低、中、高。

状态卡适合客服快速判断客户现在处于哪一步，下一句话该怎么推进。摘要和建议部分支持折叠，避免占用过多聊天空间。

### 5.8 话术页面

客户端保留话术页面，用于普通用户沉淀和查看客服剧本、知识内容、常见问题或业务资料。它更偏向客服日常使用资料库。

后台 Skill 话术包用于绑定智能体，客户端话术页面用于普通客服查阅资料。后续可以继续打通两边，让客服资料沉淀更顺。

### 5.9 导出中心

导出中心用于把聊天记录导出留档。客服可以选择账号、选择会话、设置日期范围，并创建导出任务。

导出方式按“一个账号 + 一个会话 = 一个导出任务”拆分，避免不同客户内容混到一个文件里。导出格式支持 Markdown、HTML、JSON 等形式，任务列表支持下载、批量下载和删除记录。

## 6. 云端鉴权后台功能

### 6.1 用户与邀请码

云端后台支持管理员账号登录。管理员可以创建邀请码，普通用户使用邀请码注册。管理员可以管理用户状态、权限和桌面端登录授权。

邀请码机制可以避免系统开放注册后被无关人员使用。对于团队测试和客户交付，这比完全公开注册稳得多。

### 6.2 权限控制

管理员可以控制普通用户能看到哪些功能，例如账号接入、对话查看、话术、导出中心等。管理员账号可进入后台，普通用户只使用客服工作台。

桌面端登录授权由云端控制，用户即使拿到安装包，也需要拥有有效账号和权限才能使用。

### 6.3 智能体配置

后台支持配置三类智能体。

| 智能体类型 | 用途 | 客户端是否需要选择 |
| --- | --- | --- |
| 回复智能体 | 生成三套回复策略和中文草稿 | 需要，客服可按场景选择 |
| 翻译智能体 | 检测语言并完成中外文翻译 | 不需要，由管理员选择当前生效配置 |
| 状态卡智能体 | 分析客户阶段、类型、风险、摘要和建议 | 不需要，由管理员选择当前生效配置 |

回复智能体可以创建多个，并配置不同名称、模型、提示词和话术包。比如可以配置“破冰转化助手”“费用异议助手”“入群引导助手”等，让客服根据业务场景选择。

智能体接入支持 OpenAI-compatible API，也可以接入 Coze、n8n、Webhook 等外部 Agent 服务。管理员统一维护 provider、model、base URL、API Key、提示词、温度、最大输出等参数。

### 6.4 Skill 话术包

Skill 在本产品中可以理解为“话术包”或“知识包”。一个 Skill 是一组可命名、可启停、可绑定到回复智能体的知识目录。

Skill 结构包括：

- `SKILL.md`：写清楚话术包适用场景、回复目标、表达边界和禁忌。
- `references`：放多个参考文件，例如破冰话术、费用异议、入群引导、产品说明、风险禁语。
- `assets`：登记相关素材文件。

当前版本只读取 `SKILL.md` 和 `references` 文本内容，不执行 script。这样更适合客服场景，也更安全。管理员配置好 Skill 并绑定到回复智能体后，客户端生成回复时会自动参考这些话术知识。

### 6.5 采纳数据

采纳数据用于记录客服使用 AI 辅助回复的关键动作。只有客服点击写回或发送时才会记录，普通复制粘贴或手动发送不进入这张表。

采纳数据主要字段包括 WhatsApp 账号、客户 ID、客户昵称、客户最新消息、消息接收时间、智能体、采纳方案序号、采纳方案原文、进入翻译前的中文原文、翻译结果、动作类型和操作时间。

后台以表格方式展示一条采纳信息一行，支持按账号和智能体筛选，并支持导出 CSV。这个模块适合管理者做客服质检、话术复盘、AI 效果判断和团队培训。

## 7. 典型使用流程

### 7.1 管理员配置流程

管理员先登录云端后台，创建邀请码和用户，给用户开通桌面端权限。然后配置回复智能体、翻译智能体和状态卡智能体。如果业务已有标准话术，管理员可以新建 Skill，把话术和参考资料写入 `SKILL.md` 与 references，再绑定到对应回复智能体。

配置完成后，普通用户无需知道模型 API Key，也不用理解 Agent 参数，只需要在客户端选择合适的回复智能体即可。

### 7.2 客服日常流程

客服安装 Windows 客户端后登录账号，进入账号接入页扫码登录 WhatsApp。客户发来消息后，客服在对话页查看内容；如果是外语，先点击翻译成中文；再查看用户状态卡判断客户阶段和风险。

需要回复时，客服选择合适的回复智能体，点击生成回复建议。系统生成三套方案后，客服采纳其中一套，编辑中文草稿，再翻译为客户语种。最后可以写回输入框检查，也可以直接发送。

### 7.3 管理者复盘流程

管理者进入云端后台查看采纳数据，筛选账号或智能体，检查客服采纳了什么方案、最终中文原文是什么、翻译后发送了什么。发现某类回复效果不好时，可以调整智能体提示词或 Skill 话术包，再让客服继续使用新版配置。

## 8. 当前版本状态

当前 Windows 桌面客户端已具备安装、登录、WhatsApp 扫码、对话查看、媒体消息、消息发送、AI 回复建议、多语言翻译、状态卡、话术、导出中心等核心能力。

云端鉴权后台已具备用户管理、邀请码、权限、智能体配置、Skill 管理和采纳数据查看导出能力。客户端可以使用云端后台配置好的智能体，不需要在本地重复填写 provider、model 或 API Key。

当前仍需继续验证的重点包括多账号长时间稳定性、多客服同时调用 Agent 的并发能力、不同网络和代理模式下的 WhatsApp 连接稳定性、大量历史消息下的导出速度，以及大模型 API 卡顿或格式异常时的用户体验。

## 9. 当前边界

当前产品重点是 Windows 客户端。macOS 安装包暂未完成，后续需要在 macOS 环境处理打包、签名和公证。

当前聊天记录主要保存在用户本地，没有默认做每日全量上传云端。后续如果管理者需要集中归档所有聊天记录，可以单独设计“按天上传聊天记录到云端”的能力。

当前 Skill 主要用于客服话术和文本知识注入，不执行 script。对于客服类场景，`SKILL.md` 和 references 已经能覆盖大部分需求。

## 10. 风险与合规建议

WhatsApp 对异常登录、批量群发、高频自动化和营销骚扰都有风控风险。本产品应定位为客服辅助工具，而不是批量营销工具。

建议使用时遵守几个原则：不做陌生人批量群发，不做高频自动回复，不绕过 WhatsApp 官方风控机制，不让 AI 自动替客服连续发送消息。客服应保留最终审核权，所有重要回复都经过人工采纳、编辑和确认。

在话术和 Skill 中，也应明确禁止夸大承诺、收益保证、诱导性表述和违规内容。尤其是涉及费用、收益、投资、疗效或敏感承诺的行业，更需要把禁区写进后台提示词和话术包。

## 11. 一句话总结

WhatsApp Agent 的核心价值，是把跨境客服每天重复面对的多账号、多语言、多会话、话术不统一、客户阶段难判断和回复质量难复盘这些问题，收进一个 Windows 桌面工作台里；同时通过云端鉴权后台统一管理用户、权限、智能体和话术，让客服好用，让管理者可控，让后续优化有数据可看。
