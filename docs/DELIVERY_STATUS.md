# 交付状态说明

更新日期：2026-09-10

## 当前交付结论

当前仓库已经可以作为 Windows 桌面客户端测试版本交付，云端鉴权后台与本地 WhatsApp 数据链路可以分开运行。当前版本为 `0.1.47`，本轮功能代码已提交、推送并重新打包。

客户当前可直接使用的页面包括：

- 账号接入
- 对话查看
- 导出中心
- 联系人
- IP 代理（仅桌面端）
- 管理后台中的 Provider / Model 预设、Skill 和采纳数据

## 已交付内容

### 1. 运行环境

- Docker 一键启动可用
- Web、API、PostgreSQL、agent_runner 均可拉起
- 前端构建通过
- Go 侧编译和测试通过
- 已补充 macOS / Linux 启停脚本

### 2. 账号与会话

- 创建账号
- 发起配对
- 查询状态
- 退出登录
- 删除账号

### 3. 聊天与归档

- 实时消息入库
- 聊天列表查询
- 消息历史查看
- 媒体附件落地
- 页面实时刷新
- 联系人备注、会话备注、置顶、归档、标记未读和标签
- 复制消息、引用回复和真实已读回执

### 4. Provider / Model 配置

- 管理员可以创建、编辑、启用、停用和删除 Provider。
- Provider 统一保存类型、Base URL 和 API Key；API Key 不返回浏览器明文。
- 管理员可以调用 Provider 的模型接口自动检测模型，并选择默认模型。
- 智能体只保存 Provider 引用和所选模型，不再重复保存 Base URL、API Key、思考模式或高级请求参数。
- 删除仍被智能体引用的 Provider 会被后端阻止。

### 5. 导出

- 创建导出任务
- 查询任务状态
- 每个会话分别生成文件
- 导出文件直接下载到本地
- 支持批量下载

### 6. 客户前端收口

- 首页总览已移除
- Agent 入口已隐藏
- 账号页、聊天页、导出页已按客户当前使用场景重排

### 7. 跨平台说明

- Windows / macOS 使用当前一键部署方案时，都需要先安装并启动 Docker Desktop
- Linux 可使用 Docker Engine + Docker Compose，或使用 Docker Desktop
- `.env` 需由 `.env.example` 复制生成
- 当前 `.ps1` 不是废文件，删除会导致 Windows 一键启动失效

### 8. 本轮网络修复

- 普通 Clash 代理到账号独立静态 SOCKS5 代理的链式拨号已验证。
- 修复 HTTP CONNECT 成功后误读响应体导致长连接卡住的问题。
- 增加 SOCKS5 用户名密码握手和详细拒绝原因。
- `desktop/scripts/prepare-icon.ps1` 未被构建或部署流程引用，列为清理项；其他脚本均有明确入口，不删除。

## 未完全交付内容

当前 `whatsmeow` 连接器尚未提供可用的 WhatsApp 语音/视频通话业务接口，因此本轮没有放置假按钮。需要单独评估通话协议和客户端能力后再实现。

### 2. 在线更新

当前仍未接入更新服务器、版本检查和签名更新包，不能宣称已完成在线更新。

### 3. 断线期间消息绝对补齐

当前已做到“尽量补齐”，但还不能承诺：

- 所有断线期间消息百分百补回
- 所有群消息百分百解密成功

### 2. 独立导出 worker

导出任务目前仍由 API 进程内异步执行。

### 3. 客户侧 Agent 页面

Agent 后端与服务仍在，但客户端入口已隐藏，不属于当前交付范围。

### 4. Windows 中文安装路径

打包版启动前会检查 Electron 可执行文件、资源目录和运行时目录。若安装目录包含中文或其他非 ASCII 字符，程序会给出明确提示并退出，避免本地 PostgreSQL 或运行时组件进入半启动状态。请重新安装到纯英文目录，例如 `C:\Program Files\WhatsApp Agent`；用户数据目录不随安装目录变化。
